# PurGE trial example

Tunes a `RandomForestClassifier` on the bundled Banknote dataset (already in
`datasets/Banknote/`), training on a fresh 5% subsample every trial. 80
trials total, split 50/30 across the two stages, fully automated: stage 1
runs on the full grammar, its log is pruned straight into a new grammar,
stage 2 runs on that -- no manual BNF editing.

## Run it

```
pip install -r requirements.txt   # numpy, pandas, scikit-learn already listed
python experiments/purge/purge_pipeline.py
```

## What's here

- `purge_pipeline.py` -- orchestrates stage 1 -> prune -> stage 2.
- `purge_prune.py` -- the pruning step, implementing Algorithm 1 from the
  PurGE paper (Section 3.1):
  1. Discard trials with VA below `min_accuracy` (paper: 50%).
  2. **H1**: hyperparameters whose Pearson correlation with VA exceeds
     `corr_threshold` -- pruned individually via partial dependence (the
     paper's ICE plots, Fig. 4). This applies the same way to categorical
     hyperparameters (e.g. `criterion`) as to numeric ones: a surrogate
     RandomForestRegressor is fit on the trial log, and for each H1 member
     the values/categories whose partial dependence is at or above that
     feature's own mean are kept.
  3. **H2**: hyperparameter *pairs* whose mutual correlation exceeds
     `pair_corr_threshold` -- pruned jointly via a VA heatmap over their
     value combinations (Fig. 5). This is how a hyperparameter can end up
     pruned without being individually correlated with VA (e.g. `dropout`
     in the paper's worked example, pruned only because of its correlation
     with `lr`, not with VA directly).
  4. A hyperparameter in neither H1 nor any H2 pair is left unpruned.
  5. Surviving values are written as a BNF grammar.
- `results/` -- each run writes `stage1_trials.csv`, `stage2_trials.csv` here.

Related files elsewhere in the repo:
- `src/fitness/purge_hpo.py` -- the fitness function. Trains the real model
  (not a proxy) on 5% of the data per trial. This is the "ML" case; for a
  neural net, swap in a smaller proxy architecture + a fixed low epoch count
  the same way, and use the grammar/fitness fields for that framework's
  hyperparameters instead.
- `grammars/purge/rf_banknote.bnf` -- the initial (unpruned) search space.
  `rf_banknote_pruned.bnf` is generated by stage 1, not hand-written.
- `parameters/purge_base.txt` -- shared PonyGE2 settings (selection,
  crossover, mutation), matching the paper's evolutionary configuration.

## Adapting to your own model/grammar

1. Write a grammar whose phenotype is a literal Python dict, e.g.
   `{"'n_estimators'": <n_estimators>, ...}`. Note the double-quote wrapping
   around string literals and dict keys -- PonyGE2's grammar parser strips
   the outer quote character used to delimit a literal, so a plain `'gini'`
   in the grammar produces the bare phenotype text `gini` (invalid Python).
   Wrapping in `"..."` instead, i.e. `"'gini'"`, is what survives into a
   valid quoted string in the phenotype.
2. Point `FITNESS_FUNCTION` in `purge_base.txt` at your fitness module, and
   write that module (copy `purge_hpo.py` as a starting point) to decode the
   phenotype and train your actual model.
3. Update `BASE_GRAMMAR`, `DATASET_TRAIN`/`DATASET_TEST`, and
   `POPULATION_SIZE` in `purge_pipeline.py` / `purge_base.txt` to match.

`purge_prune.py`'s `corr_threshold` / `pair_corr_threshold` (how easily a
hyperparameter enters H1/H2) and `min_accuracy` (the VA floor before any of
this runs) are the knobs most worth revisiting for your own search space --
with only 50 stage-1 trials, correlations are noisy, so don't over-read a
single run's H1/H2 membership.

## Results layout (multi-run, multi-dataset)

```
results/
  runs_index.csv                     <- one row per run, across every dataset
  <DATASET_NAME>/
    <run_id>/
      stage1_trials.csv              <- every trial attempted, incl. failures (status=error)
      stage2_trials.csv
      pruned_grammar.bnf             <- copy of the grammar stage 2 actually ran on
      manifest.json                  <- thresholds, pruned search space, best config per stage
```

`run_id` is `<UTC timestamp>_<6-char uuid>`, generated fresh each run and
passed to the fitness function via `PURGE_RUN_ID`/`PURGE_DATASET`/
`PURGE_STAGE` env vars, so every row in every trial CSV is traceable back to
exactly which run/dataset/stage produced it -- safe to concatenate all of
`results/**/stage*_trials.csv` for cross-run analysis.

A trial that raises an exception (bad phenotype, degenerate data split, an
invalid sklearn parameter combination) is still written to the CSV with
`status=error` and the exception message in `error`, rather than silently
vanishing -- `purge_prune.py` excludes these from the correlation/PDP
analysis but tells you how many it excluded.

To run a second dataset, change `DATASET_NAME` in `purge_pipeline.py` (and
point `parameters/purge_base.txt` / `purge_hpo.py` at that dataset's files)
-- results land in their own `results/<dataset>/` subtree automatically.
